# 等角予測による分布によらない予測区間

**卒業研究 2026年度（R08）後期 ／ 東京理科大学 理学部第一部 応用数学科 黒沢研究室**

予測モデルにもデータ分布にも仮定を置かず、有限個のデータだけで被覆率 $1-\alpha$ を
保証する予測区間（conformal prediction）を、定理の証明・シミュレーション・実データの
3層で扱う。

---

## 研究の問い

| | 問い | 対応する実験 |
|---|---|---|
| **RQ1** | 有限標本被覆保証は実際にどの程度正確に成り立つか。理論の上下界 $1-\alpha \le P \le 1-\alpha+1/(n+1)$ を実測は挟めるか | E1 |
| **RQ2** | 予測区間の**幅**は、下敷きモデルと非適合度スコアの選び方でどう変わるか | E2, E5, E6 |
| **RQ3** | 保証が壊れるのはどんなときか。条件付き被覆と交換可能性の破れという2つの限界 | E3, E4 |

---

## クイックスタート

```bash
# 1. プロジェクト直下に venv を作る（初回のみ）
python3 -m venv --system-site-packages .venv
.venv/bin/python -m pip install -e ".[dev]"

# 2. 実行（make が .venv/bin/python を使うので PYTHON の指定は不要）
make test      # 検証テスト（実装を信用する唯一の根拠）
make e1        # 実験E1を実行 -> results/*.csv
make e1b       # 実験E1b（検証の水準と誤りの検出力）
make e2        # 実験E2（下敷きモデルへの非依存性）
make figures   # csv から figures/*.pdf を再生成
```

`--system-site-packages` は**必須**。これを付けないと numpy 等が最新版で入り直され、
rf/gbm/mlp の学習結果が変わって `results/*.csv` が再現しなくなる。
検証済みのバージョンは `docs/環境.txt` を参照（numpy 1.26.4 / scikit-learn 1.3.0 /
pandas 1.5.3 / matplotlib 3.7.1 / mapie 0.9.2）。

venv を使わない環境では `make PYTHON=python3 test` のように指定する。

**実装は Claude Code で行います。貼れるプロンプトは `docs/ClaudeCodeプロンプト集.md`。**
進め方は **`docs/実行計画.md`** を見てください。 週次のスケジュール、マイルストーンの
判定基準、遅れたときの縮退プランがまとまっています。

`make e1` は約5秒、`make e2` は約1分、`make test` は約2秒で終わる。

### 現状の実行結果（E1）

| n | α | 下界 | 実測 | 上界 | se_trial | se_test | 支配成分 | 判定 |
|---|---|---|---|---|---|---|---|---|
| 20 | 0.10 | 0.9000 | 0.9029 | 0.9476 | 0.001947 | 0.000936 | 試行間 | OK |
| 50 | 0.10 | 0.9000 | 0.9022 | 0.9196 | 0.001314 | 0.000939 | 試行間 | OK |
| 100 | 0.10 | 0.9000 | 0.9010 | 0.9099 | 0.000938 | 0.000944 | **テスト集合** | OK |
| 500 | 0.10 | 0.9000 | 0.8996 | 0.9020 | 0.000428 | 0.000950 | **テスト集合** | OK |
| 2000 | 0.10 | 0.9000 | 0.8994 | 0.9005 | 0.000209 | 0.000951 | **テスト集合** | OK |

被覆率の経験分布は理論の $\mathrm{Beta}(n+1-l,\, l)$ と一致する（`figures/fig_e1_coverage_beta_alpha10.pdf`）。

平均被覆率に付ける区間は2成分の合成。`se_trial` は較正集合の引き直しによる試行間の
ばらつきで試行数 R とともに縮むが、`se_test` は固定テスト集合（10万点）1つ分の
二項ノイズで、全試行に共通のバイアスとして乗るため**試行数を増やしても消えない**。
そのため n が大きくなるほど支配成分が入れ替わり、n=2000 では分散の 95.4% を
テスト集合成分が占める。詳細は CLAUDE.md「報告の作法」を参照。

## 設計上の約束

1. **実験の実行と作図を分離する。** 実験は csv を吐き、図は csv から作る。
   実験を回し直さずに図だけ直せる状態を保つ（締切前に効く）。
2. **仕様書を書いてから実装する。** `specs/` に仕様がない実験は作らない。
   仕様書はそのまま卒論第5章の下書きになる。
3. **テストは理論から書く。** 「実装がこう動く」ではなく「理論がこう言う」で書く。
   これが生成AIの書いたコードを信用できる唯一の根拠になる。
4. **共形分位点は `ceil((n+1)(1-alpha))`。** `np.quantile` を使わない。
   詳細は `CLAUDE.md`。
