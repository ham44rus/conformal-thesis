### 第3締切の性質（最重要）

- 第0〜第2締切は**目安**。第3締切は**厳格で一日たりとも待たない**
- 製本依頼・成績付け・入試日程の都合による
- **「とりあえず作ったものを出す日」ではなく、「この日までに黒沢先生からOKをもらい完成版を提出する日」**

> **実務的な帰結**：実質の締切は 12月15日（第1版）です。年内初稿ではなく
> **12月15日初稿**で逆算してください。docs/研究計画.md のスケジュールはこれに合わせてあります。

## 4. 卒論原稿の注意（受け付けてもらえない条件）

以下に該当すると**受理されません**。

- `There were undefined references.` が残っている
- 参考文献に **`\bibitem` を使っている**（**pbibtex での処理が必須**。先生配布のbibサンプルを参照）
- **pbibtex で Warning が出ている**

提出するのは **TeX・bib・画像（eps等）の3種類のみ**。コンパイル済みpdfは不要。
卒論フォーマットの**第3章を熟読**すること。

## 5. データ・プログラムの提出要件（本リポジトリに直結）

| 要求 | 本リポジトリでの対応 |
|---|---|
| 複数ファイルがある場合は `Readme.txt` を作成し、各ファイルの意味を説明 | `submission/Readme_template.txt` |
| プログラムを書いた場合、`Readme.txt` に**実行手順**を記載 | 同上 |
| プログラム内に**コメントを十分に書く**（他人が見て理解できるか） | `CLAUDE.md`「実装方針」に規定 |
| できれば**卒論のどこに該当するかをコメントで記載** | 各モジュール冒頭の「対応箇所」コメント |
| Excel提出時は `Readme` シートを用意し、各シートの説明を書く | csv中心にするので該当しにくい。使う場合は要対応 |
| 変数名が `x` のままなど意味不明なものを残さない | コードレビュー時の確認項目 |
| Python を spyder で書いた人は `.py` を提出 | `src/` と `experiments/` の `.py` をそのまま提出 |
| Jupyter を使った場合は `.ipynb` に加え**コードをpdfにしたもの**も提出 | 本研究は `.py` 中心にするため該当しない見込み |
| 秘匿データ・非公開データ・個人情報を含むデータは提出しない | 本研究は公開データ（UCI）と人工データのみ |

## 6. その他

- 提出後、黒沢先生に**報告**し、OKをもらってから `提出状況.xlsx` の該当欄に○を付ける
- 卒論は後輩やオープンキャンパスの来訪者に見せることがある。問題がある場合は事前に申し出る
- 卒業前に：貸出図書（**ゼミのテキスト**）の返却、内部推薦者の手続き確認、
  外部大学へ進む場合は辞退届
