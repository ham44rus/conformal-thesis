# E1b: 検証の水準と、誤りの検出力

対応：卒論 第5章 E1b の節（`sec:e1b`）／ 実装 `experiments/e1b_detection_levels.py`

## 目的

被覆保証の検証には水準がある。どの水準ならどの誤りを検出できるのかを実演する。

| 水準 | 何を確かめるか |
|---|---|
| L0 | 点推定を眺めるだけ |
| L1 | 下界 `1-alpha` を満たすか |
| L2 | 上界 `1-alpha + 1/(n+1)` も満たすか |
| L3 | 被覆率の分布が `Beta(n+1-l, l)` と一致するか |

## 手続き

n=1000, alpha=0.10, 試行2000。以下の3ケースを比較する。

1. **correct** … 正しい実装 `k = ceil((n+1)(1-alpha))`
2. **offbyone** … 誤実装 `k = ceil(n(1-alpha))`（最頻出のバグ）
3. **small_test** … 実装は正しいが、被覆率をテスト2,000点で推定した場合

1と2の被覆率は400万点のテスト集合で「真値」として評価する。
（テスト集合が小さいと、その集合固有のズレが全試行に共通のバイアスとして乗り、
正しい実装まで棄却されてしまう。この現象自体がケース3の主題でもある。）

## 出力

`results/e1b_detection_levels.csv` : 列 = [case, trial, coverage]

## 実行結果（seed=7）

理論分布 Beta(901,100)、平均 0.90010、標準偏差 0.00947、上下界 [0.90000, 0.90100]（幅 0.00100）

| ケース | 平均 | 標準偏差 | L1 | L2 | 平均のz | L3 KS p |
|---|---|---|---|---|---|---|
| 正しい実装 | 0.90025 | 0.00950 | ○ | ○ | +0.72 | 9.1e-01 |
| 誤実装 (n+1→n) | 0.89927 | 0.00955 | × | × | −3.94 | 1.3e-04 |
| テスト集合が小さい | 0.90038 | **0.01140** | ○ | ○ | **+1.33** | **1.5e-08** |

## 検証（この実験が正しく走ったと判断する基準）

- 正しい実装が L1・L2・L3 のすべてを通る
- 誤実装が L1 と L3 の両方で検出される
- テスト集合が小さいケースが **L1・L2 を通ってしまい、L3 でのみ検出される**

## この実験の主張（第5章に書くこと）

**位置のずれは平均が、形のずれは分布が捕まえる。両方を見て初めて検証したと言える。**

- off-by-one は被覆率を **0.001 しか動かさない**（0.90025 → 0.89927）。
  値を眺めるだけ（L0）では絶対に気づけない。一方で理論平均との z は −3.94 で、
  平均の検定でも分布の検定でも検出できる。**位置のずれだからである。**
- テスト集合が小さいケースは、平均が z=+1.33 と完全に正常に見える。
  しかし標準偏差が理論の **1.20倍**に膨らんでおり、KS検定は p=1.5e-08 で棄却する。
  **形のずれは平均には映らない。**
- 上下界の幅は 0.00100 しかないのに、試行ごとの被覆率の標準偏差は 0.00947。
  **帯の約10倍ばらつく。** 1回の実験では上下界を確かめられず、多数回の平均で初めて挟める。

## 図（`experiments/make_figures.py: fig_e1b_ecdf`）

`figures/fig_e1b_ecdf.pdf` … 3 ケースの被覆率の**経験分布関数**と、理論の Beta(901, 100) の
分布関数を 1 枚に重ねる。

- 横軸は被覆率、縦軸は累積確率。理論の分布関数は太い線、3 ケースの経験分布関数は階段で重ねる
- 縦線で下界 1−α = 0.90 と上界 1−α+1/(n+1) = 0.90100 を示す（帯の幅 0.001 が
  分布の広がり（SD 0.00947）に比べていかに狭いかが見える）
- 読み取り：誤実装は曲線全体が左にずれる（位置のずれ）、テスト集合が小さいケースは
  中央で交差して両裾が外に出る（形のずれ）、正しい実装は理論に重なる
- 生成の乱数は使わない（csv から決定的に描く）。同じ csv から 2 回作って pdf・png が一致すること

## 付随する論点

較正集合の使い回し、サンプリングの相関など、平均を保ったまま分散だけを変える誤りは
他にもある。L3 の検査はこれらをまとめて捕まえる。生成AIが書いたコードを信用する根拠として、
L3 まで見ていることが重要になる（付録B）。
